## 2.堆

    新生代(Eden 区/Survivor区 8:1:1):
        占用堆的1/3,用于存放新生的对象。

        Eden:
        Java新对象的出生地(注：若新对象占用内存过大，直接分配到老年代),内存不够时触发GC。

        Servivor：
        上次GC的幸存者。
    老年代:
        占用堆的2/3,存放生命周期长的内存对象。老年代不会频繁的GC,当新生代进入老年代,
        导致内存不够时或没有足够大的连续内存空间，才会发生GC。

## 3. MetaSpace

类的元数据存放在这里，在JDK7(含)是在堆里的Permgen，从JDK8之后是一块儿独立的空间。

包括方法字节码、符号、常量池(不包含字符串常量池)、注解等类信息。加载的类越多，使用的元数据就越多。

可以通过 -XX:MaxMetaspaceSize（默认无上限）选项控制元数据总大小。

![MetaSpace.png](https://blog.touchfishes.com//assets/images/2024/jvm/MetaSpace.png)


## 4. Compressed Class Space

MetaSpace中的一段单独的空间，存的是堆内的各个java对象实例的对象头中压缩类指针指向的类实例信息。
可以通过 -XX:CompressedClassSpaceSize（默认1G）选项控制元数据总大小。

具体解释：

一个运行中的JVM堆中存在着大量的java对象实例，每个对象实例都有三部分组成：

* Object Header: 这部分一般有 Mark Word 和 Klass pointer 部分组成。前者的是锁和gc相关，后者为指向类信息的指针。

* Instance Data: 我们在 .java 文件中定义的各种字段信息。

* Padding: 4位系统需要8字节对齐，不足部分需要填充。

而这块儿空间是和 Klass pointer 有关的，对于64位系统：

如果关闭 -XX:-UseCompressedOops 则它的头信息


```
|----------------------------------------------------------|
|                 Object Header (128 bits)      |
|--------------------------------|-------------------------|
|   Mark Word (64 bits)      | Klass pointer (64 bits) |
|--------------------------------|-------------------------|
开启了 -XX:+UseCompressedOops 和 -XX:+UseCompressedClassPointers 后

|----------------------------------------------------------|
|                 Object Header (96 bits)       |
|--------------------------------|-------------------------|
|   Mark Word (64 bits)      | Klass pointer (32 bits) |
|--------------------------------|-------------------------|
```


会节省4字节。开启和关闭的影响：

* 优点： 对于一个JVM堆而言，里面的对象示例是数以万计的，可以节省堆内存使用。
jvm虚拟机栈可以使用CPU高速缓存，这部分空间更宝贵，压缩指针能提高这部分使用效率。

* 缺点：寻址最大支持堆32G



因为现阶段JVM的堆都会小于32G，因此JVM其实默认是开启压缩的，正因为开启了这个压缩，它的地址部分也是32位的，
存放的地方也是MetaSpace中的一个单独的空间，这个空间就是 Compressed Class Space。

## 5. Code Cache

存放JIT生成的机器码(native code)，JNI的机器码也放在这里，不过JIT编译生成的native code占主要部分。
通过 -XX:+PrintCodeCache 参数可以打印出大小。


![Cache.png](https://blog.touchfishes.com//assets/images/2024/jvm/Cache.png)

## 7. JVM Method stack

一般来说线程部分 committed内存 等于 Xss * 线程数，但是实际运行中Java 线程的实际内存使用会小于这个值，通常每个线程堆栈占用80至200KB。
